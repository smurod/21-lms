## Цель простыми словами

У нас есть DataLens — программа, которая умеет рисовать графики и дашборды.
Мы делаем маленький AI-сервис `datalens-ai`.

Человек пишет в чат:

> Визуализируй мою базу данных

Сервис должен:

1. посмотреть, какие таблицы и колонки есть в базе;
2. придумать несколько полезных графиков;
3. написать SQL для каждого графика;
4. проверить SQL, чтобы он точно работал;
5. создать в DataLens подключение к базе;
6. создать QL-чарты напрямую по SQL;
7. собрать из этих чартов дашборд;
8. вернуть ссылку на готовый дашборд.

Позже человек сможет редактировать дашборд словами:

> добавь график по таблице users
> поменяй второй график на столбчатый
> удали график с заявками

## Зафиксированные решения пользователя

1. **QL-чарты без отдельных dataset.**
   Графики через подключение и SQL. Dataset не используем.

2. **Auth-порт публикуем на хост.**
   Auth доступен с хоста `127.0.0.1:8088`.

3. **Workbook `AI Generated`.**
   Все автоматические объекты складываем туда, не в `21_lms_workbook`.

4. **Первая версия чартов — только проверенные типы.**
   `line`, `column`, `table`.
   Pie, indicator/metric и фильтры — позже, когда будут шаблоны.

5. **Dashboard production-like.**
   Ориентир — OpenSource Demo: заголовок, секции, две колонки для column, line/table на всю ширину.
   KPI-ряд отложен: нет шаблона metric.

6. **Объяснять просто.**

7. **Laravel будет потом.**
   После готовности и тестов: ссылка, iframe или страница.
   Сейчас фокус на AI-сервисе. Laravel-интеграцию не начинать, пока не решена стратегия MySQL (A/B/C).

## Адреса базы данных

- `datalens-ai` на ноутбуке видит базу как `localhost` / `127.0.0.1` (`DB_URL`);
- DataLens в Docker видит `localhost` как себя, поэтому хост БД для него — `172.17.0.1` (`DATALENS_DB_*`).

Два адреса обязательны.

## API DataLens, которое использует код

Единый вход gateway:

```text
POST http://localhost:8085/gateway/root/<service>/<action>
```

Логин: `POST http://127.0.0.1:8088/signin` → куки `auth`, `auth_exp`.

Что реально вызывает `datalens_client.py`:

- `us.getWorkbooksList`, `us.createWorkbook`;
- `bi.createConnection`, `bi.deleteConnection`;
- `us.getEntries`, `us._deleteUSEntry`;
- `mix.createDashboardV1`, `mix.getDashboardV1`, `mix.updateDashboardV1`;
- QL-чарты: **HTTP** `POST/DELETE /api/charts/v1/charts`, не `mix.__createQLChart__`.

Ограничения текущего кода:

- только PostgreSQL;
- `chart_count` из запроса передаётся в pipeline; без него масштаб dashboard определяет LLM;
- `dashboard_url` указывает на workbook;
- нет cleanup при ошибке generate;
- нет `/api/chat`, `/api/generate-sql`, `/api/create-dashboard`;
- типы чартов только line/column/table;
- синхронный psycopg в async;
- нет Docker-образа самого datalens-ai.
