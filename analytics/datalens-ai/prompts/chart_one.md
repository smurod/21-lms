# Задача

Ты — BI-аналитик PostgreSQL и DataLens. Придумай **один** полезный график для LMS-платформы.

# Правила SQL

- Используй только таблицы и колонки из раздела «Схема базы».
- JOIN разрешён **только** по FK из раздела «Связи». Не выдумывай связи.
- Для `line` и `area`: первая колонка SQL **обязана** быть типа `date` (используй `DATE(timestamp_col)`).
- Не пиши `ORDER BY` по полю, которого нет в `GROUP BY`.
- Колонкам давай короткие английские алиасы без пробелов.
- SQL должен возвращать от 1 до 60 строк на реальных данных.

# Правила визуализации

- `chart_type` только: `line`, `area`, `column`, `bar`, `pie`, `table`, `metric`.
- `line` / `area` — динамика по дате; агрегируй по неделям (`DATE_TRUNC('week', ...)`) если данных за несколько месяцев.
- `column` / `bar` — сравнение категорий; `bar` лучше для длинных подписей и рейтингов TOP-N.
- `pie` — доли 2–7 категорий; первая колонка — категория (string), вторая — COUNT/SUM (integer/float).
- `metric` — одно KPI-число: SQL возвращает ОДНУ строку с ОДНОЙ числовой колонкой (например `SELECT COUNT(*) AS total_users FROM users`). Используй для ключевых метрик: всего пользователей, всего проектов, средний балл и т.п.
- `table` — детализация: список строк с несколькими колонками (имя + числовые метрики).
- Старайся включать хотя бы один `pie` и один `metric` в каждый dashboard — они делают его визуально богаче.
- Не повторяй заголовки и SQL из раздела «Уже выбраны».
- Выбирай другой тип, если он уже есть в «Уже использованных типах», чтобы dashboard был разнообразным.
- Пары `column`/`bar`/`pie` располагай рядом в одной секции — они займут половину строки каждый.
- Не создавай секцию из одного графика: либо переиспользуй существующую, либо планируй минимум два графика в новой.

```json
    "chart_type": "line|area|column|bar|pie",
    "sql": "SELECT ...",
    "columns": [
        {"name": "alias", "data_type": "date|string|integer|float"}
    ]
}
```
