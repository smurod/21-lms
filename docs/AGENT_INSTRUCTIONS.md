## ФАЗА 1. ПОСТРОЕНИЕ ЗЕРКАЛА (до любых правок)

1.1. Пользователь пришлёт файл структуры проекта (PROJECT_STRUCTURE.md или
     аналог). Помести его в `docs/PROJECT_STRUCTURE.md`. Это единственный
     источник истины о путях. При конфликте «догадка vs структура» — структура.

1.2. **Файлы приходят ПЛОСКИМИ** (в `/home/user/uploads/`, без путей) и
     в большинстве случаев ПЕРЕИМЕНОВАНЫ в `.txt` для прохождения валидации
     загрузки. Твоя обязанность — детерминированное восстановление:
     a) отрезать суффикс `.txt`, восстановив исходное расширение
        (`web.php.txt` → `web.php`; `header.blade.txt` → `header.blade.php`);
     b) определить путь размещения по `docs/PROJECT_STRUCTURE.md` и по
        содержимому файла (namespace, @extends, use-декларации);
     c) при неоднозначности (два кандидата-пути) — НЕ угадывать, а задать
        вопрос пользователю, перечислив кандидатов;
     d) файл кладётся в workspace БАЙТ-В-БАЙТ как получен (никаких правок
        при размещении — зеркало прежде трансформаций).

1.3. Workspace обязан быть изоморфен проекту: путь в workspace ≡ путь
     относительно `~/projects/21-lms/`. Пример: `routes/web.php` здесь
     соответствует `~/projects/21-lms/routes/web.php` там.

1.4. Заверши фазу отчётом: таблица «получен → размещён по пути → md5».

## ФАЗА 2. РАБОЧИЙ ЦИКЛ (повторяется для каждой задачи)

2.1. Зеркалирование входящих файлов (Фаза 1.2) — всегда первым шагом.
2.2. Правки выполняются ТОЛЬКО в workspace, инструментами, не «в уме».
2.3. Каждая правка сопровождается верификацией, адекватной типу файла:
     - CSS: баланс `{`/`}` равен 0 (python-подсчёт), стили дописываются
       строго В КОНЕЦ файла;
     - JS: `node --check` без ошибок;
     - Blade/PHP: визуальная проверка парности директив (@if/@endif,
       @section/@endsection); php-линтер в контейнере недоступен.
2.4. Отчёт пользователю обязан содержать:
     a) причинно-следственное объяснение (что было сломано и почему);
     b) таблицу переноса: файл workspace → ПОЛНЫЙ путь назначения
        `~/projects/21-lms/...` (формулировка «туда же» ЗАПРЕЩЕНА);
     c) md5-эталоны всех изменённых файлов;
     d) команды пост-обработки (`php artisan view:clear` и т.п.);
     e) команды удаления устаревших файлов, если применимо.
2.5. «Отправка» файла пользователю = файл существует в workspace + его путь
     упомянут в тексте ответа в бэктиках (интерфейс Arena рендерит карточку).
     Код в ```-блоках как способ передачи файлов ЗАПРЕЩЁН (портит отступы),
     кроме случая, когда пользователь просит показать код явно.
2.6. Сверка: пользователь возвращает md5. При расхождении — каскад:
     обычный md5 → `sed 's/\r$//' | md5sum` (CRLF) → `tr -d ' \t\r\n' | md5sum`
     (форматирование). Совпадение на третьем уровне = код идентичен,
     форматирование пользователя принимается эталоном (обновить workspace
     его версией при следующей пересылке). Расхождение на третьем уровне =
     запросить файл и делать diff.
2.7. К следующей задаче — только после закрытия сверки текущей.

## ИНВАРИАНТЫ КОДА (нарушение = брак)

I. JavaScript не содержит бизнес-логики. Допустимо: открытие/закрытие
   модалок, подсветка, копирование в буфер, автоскрытие тостов, анимации.
   Запрещено: fetch/AJAX, валидация данных, редиректы (кроме перехода по
   data-атрибуту, отрендеренному сервером), вычисление состояний.
   Вся логика — Laravel: нативные формы POST/DELETE, redirect + flash,
   `$request->validate()`, ошибки через `$errors`/`old()`.

II. Публичная часть подключает ровно ОДИН css (`public/assets/css/style.css`)
    и ровно ОДИН js (`public/assets/js/app.js`). Новые стили — только
    дописыванием в конец style.css.

III. Миграции не плодятся: изменения схемы сливаются в исходные
     create_*-миграции (пользователь выполняет migrate:fresh); add_*/alter_*
     файлы после слияния удаляются с обеих сторон. Результирующая схема БД
     обязана остаться эквивалентной.

IV. Роуты: именованные (`route('...')`); несуществующий роут в вёрстке —
    заглушка `#имя`, замена на route() при появлении роута.

V. Blade-география: layouts — `resources/views/public/layouts/`,
   компоненты — `resources/views/public/components/`, проекты —
   `resources/views/public/projects/{index,map,show}.blade.php`,
   auth — `resources/views/auth/`.

VI. Язык общения — русский; технические термины допустимы на английском.
